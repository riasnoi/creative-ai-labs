1. Цель и результаты 
Цель. Научиться сравнивать модели text-to-image по протоколу, при котором 
различие вызвано моделью, а не условиями запуска: одинаковый бриф, одинаковые seed, 
каждая модель в своей заданной конфигурации (она входит в «модель»), измерения с 
оценкой разброса, отдельно время без загрузки, слепая оценка глазами и запись ограничений. 
Результаты. После работы студент: 
1. объясняет, почему при сравнении моделей сравниваются конфигурации целиком 
(веса, планировщик, число шагов, управление, размер кадра), и записывает их в 
паспорт; 
2. выполняет сравнение двух моделей н а пяти seed и отличает разность, превосходящую 
разброс, от случайной; 
3. разделяет три вида вывода – статистически значимое различие, практически важное 
различие и различие, видимое глазами при слепой оценке; 
4. корректно измеряет время генерации (без загрузки в есов и прогрева) и сопоставляет 
его с качеством; 
5. называет угрозы валидности сравнения (одна пара брифов, малое число seed, метрика 
CLIP, различия в размере кадра) и лицензии моделей.

2.4. Схема сравнения и значимость 
Модель A и модель B выполняются на seed 101…105 с одним брифом. Для каждой 
метрики: среднее A, выборочное стандартное отклонение 𝑠 модели A по seed, среднее B, 
разность 𝛥 = 𝐵‾ − 𝐴‾, отношение |𝛥|/𝑠 и признак |𝛥| > 2𝑠. Допуск на практическую пользу 
записывается до запуска (в образце: clip_brief и clip_text – 1,0 пункта; edge и contrast – 10 % 
от значения A; время – отношение в 1,5 раза). Признак 2𝑠 – консервативное правило ЛР 6, а 
не проверка гипотезы: при пяти seed он часто не срабатывает у небольших, но устойчивых 
различий (раздел 6.5). 
Одно сравнение – не вывод о моделях: бриф один, seed пять, значения меняются от 
брифа к брифу. Итог по четырём моделям даёт лишь совокупность 30 вариантов группы 
(раздел 10). 
2.5. Слепое сравнение 
Метрика CLIP не заменяет глаз, поэтому вторая часть работы – слепая экспертная 
оценка: студент получает пять листов blind_<seed>.png (изображения моделей A и B для 
одного seed, порядок слева и справа случаен и записан в blind_key.json), выбирает 
изображение, лучше соответствующее брифу, и только потом открывает ключ. Важное 
ограничение: пять пар — слишком мало. Если одна модель выиграла все пять пар, 
двусторонняя вероятность такого исхода при равенстве моделей равна 2 ⋅ (1/2)5 = 0,0625 — 
выше 0,05; значит, даже «5:0» не позволяет отвергнуть равенство на уровне 0,05. Итог 
слепой оценки записывается как наблюдение, а не как доказательство. 
2.6. Что нельзя выводить 
(1) Модель «лучше» вообще: сравнение относится к одному брифу, пяти seed и данной 
конфигурации. (2) Причину различия: A и B различаются сразу по нескольким 
факторам (веса, шаги, управление, размер), разделить их этим сравнением нельзя. (3) 
Скорость на другом оборудовании: время получено на процессоре Engee. (4) Качество 
по clip_brief: метрика видит соответствие тексту, а не эстетику и не дефекты.

6.4. Намеренно введённые ошибки 
Ошибка 1: вывод по одному seed. Если сравнить SD Turbo и LCM только по 
clip_brief на одном seed, получатся противоположные выводы: на seed 105 – 25,50 и 24,60 (Δ 
= −0,90, «SD Turbo лучше»), на seed 103 – 24,21 и 27,79 (Δ = +3,58, «LCM заметно лучше», в 
4,5 раза больше 𝑠 = 0,80). Симптом: разности по seed от −0,90 до +3,58, среднее +0,56. 
Диагностика: выписать значения по всем seed и разброс модели A. Исправление: пять seed, 
среднее, 𝑠 и признак 2𝑠 (раздел 2.4). 
Ошибка 2: «уравнивание» числа шагов.  Чтобы сравнение было «честным», LCM 
запущен с одним шагом, как SD Turbo (L.variant_summary(1, save_dir="v01_err", cfg={"lcm": 
{"steps": 1}})). Результат: clip_brief LCM 21,71 против 25,17 у SD Turbo (Δ = −3,46, |𝛥|/𝑠 = 
4,3 – «значимо хуже»); время 22,24 с против 21,48 с (« LCM не быстрее»). Изображения 
размыты, фигуры «плавают» (demo_journal/error_lcm_1step.png): 
 
Ошибка 2: LCM при одном шаге, seed 101–105 
Симптом: результат LCM резко хуже, чем при четырёх шагах ( clip_brief 25,73), и 
«выигрыш в скорости» исчез. Диагностика: сверить конфигурацию в паспорте с примером 
карточки модели – LCM в примере запускается на 4 шагах (карточка допускает 1 –8). 
Исправление: каждую модель запускать в заданной конфигурации (таблица 2.2); если нужно 
сравнить число шагов – это отдельный эксперимент, в котором модель одна, а меняется 
число шагов. 
Ошибка 3: время из разных сеансов.  Если взять время SD Turbo из полного прогона 
(17,22 с), а время LCM – из демонстрационного запуска (36,79 с), отношение получится 2,14, 
тогда как в каждом сеансе отдельно – 1,76 и 1,75: отношение завышено на 21 %. Симптом: 
время одной и той же конфигурации в двух запусках отличается на 20 % и более. 
Диагностика: сравнить время повторно измеренной модели в двух сеансах. Исправление: обе 
модели пары измерять в одном запуске (это делает variant_summary) и сообщать отношение, 
а не разность в секундах.

def load_model(key): 
    c = MODELS[key] 
    pipe = DiffusionPipeline.from_pretrained(c["repo"], revision=c["revision"], torch_dtype=torch.float3
2, safety_checker=None, 
                                             requires_safety_checker=False, use_safetensors=True) 
    if c.get("scheduler") == "dpm": 
        pipe.scheduler = DPMSolverMultistepScheduler.from_config(pipe.scheduler.config) 
    pipe.set_progress_bar_config(disable=True) 
    return pipe 
 
 
def load_clip(): 
    model = CLIPModel.from_pretrained(CLIP_ID, revision=CLIP_REVISION, use_safetensors=True).eval(
) 
    return model, CLIPProcessor.from_pretrained(CLIP_ID, revision=CLIP_REVISION) 
 
 
def generate(pipe, key, prompt, seed, cfg=None): 
    """cfg — необязательные замены параметров конфигурации (например, dict(steps=1)); нужны 
только для учебных ошибок.""" 
    c = {**MODELS[key], **(cfg or {})} 
    g = torch.Generator("cpu").manual_seed(seed) 
    t0 = time.perf_counter() 
    img = pipe(prompt, num_inference_steps=c["steps"], guidance_scale=c["guidance"], height=c["size"],
 width=c["size"], generator=g).images[0] 
    return img, time.perf_counter() - t0 
 
 
@torch.no_grad() 
def clip_sims(clip, img, texts): 
    """Косинусное сходство изображения с текстами в CLIP, умноженное на 100 (не CLIPScore).""" 
    model, proc = clip 
    inp = proc(text=list(texts), images=img, return_tensors="pt", padding=True, truncation=True) 
    out = model(**inp) 
    a = out.image_embeds / out.image_embeds.norm(dim=-1, keepdim=True) 
    b = out.text_embeds / out.text_embeds.norm(dim=-1, keepdim=True) 
    return [float(v) * 100 for v in (a @ b.T)[0]] 
 
 
def luma256(img): 
    """Яркость изображения, приведённого к 256×256 (чтобы размер кадра не влиял на энергию гр
аниц).""" 
    x = np.asarray(img.convert("RGB").resize((256, 256)), dtype=np.float64) / 255 
    return 0.299 * x[..., 0] + 0.587 * x[..., 1] + 0.114 * x[..., 2]

def edge_energy(img): 
    y = luma256(img) 
    return float(np.mean(np.hypot(ndimage.sobel(y, axis=0), ndimage.sobel(y, axis=1)) / 8)) 
 
 
def contrast(img): 
    return float(np.std(luma256(img))) 
 
 
def measure(pipe, clip, key, ctx, seed, cfg=None): 
    """Одно изображение: метрики и время генерации, с (без загрузки модели).""" 
    img, dt = generate(pipe, key, BRIEFS[ctx], seed, cfg) 
    s = clip_sims(clip, img, [BRIEFS[ctx], TEXT_PROBE]) 
    return dict(clip_brief=s[0], clip_text=s[1], edge=edge_energy(img), contrast=contrast(img), seconds
=dt), img 
 
 
def compare(a_list, b_list): 
    """Сводка: для каждой метрики среднее A, s (по seed режима A), среднее B, разность, |d|/s, призн
ак |d| > 2s.""" 
    rows = [] 
    for m in METRICS: 
        A = [r[m] for r in a_list]; B = [r[m] for r in b_list] 
        d = float(np.mean(B) - np.mean(A)); s = float(np.std(A, ddof=1)) 
        rows.append((m, float(np.mean(A)), s, float(np.mean(B)), d, abs(d) / s if s > 0 else float("inf"), boo
l(abs(d) > 2 * s))) 
    return rows 
 
 
def variant_summary(n, seeds=SEEDS, save_dir=None, cfg=None): 
    """Вариант n = 1..30: бриф c = (n-1)//6, пара k = (n-1)%6. Модели загружаются по очереди (памя
ть). 
    save_dir — папка для изображений (файлы <модель>_s<seed>.jpg); cfg — замены конфигурации 
по моделям (только для учебных ошибок).""" 
    c, k = (n - 1) // 6, (n - 1) % 6 
    clip = load_clip() 
    res = {} 
    if save_dir: 
        os.makedirs(save_dir, exist_ok=True) 
    for key in PAIRS[k]: 
        pipe = load_model(key) 
        generate(pipe, key, BRIEFS[c], 0, (cfg or {}).get(key))      # прогрев 
        res[key] = [] 
        for s in seeds: 
            r, img = measure(pipe, clip, key, c, s, (cfg or {}).get(key)) 
            if save_dir: 
                img.save(os.path.join(save_dir, f"{key}_s{s}.jpg"), quality=90)

            res[key].append(r) 
        del pipe; gc.collect() 
    return dict(variant=n, ctx=c + 1, pair=PAIRS[k], rows=compare(res[PAIRS[k][0]], res[PAIRS[k][1]])
) 
 
 
def blind_sheets(n, folder, seeds=SEEDS): 
    """Листы для слепого сравнения: для каждого seed — пара изображений A и B, порядок слева и 
справа случаен (фиксируется номером варианта). 
    Пишет folder/blind_<seed>.png и folder/blind_key.json (какая модель слева); ключ откройте тол
ько после выбора.""" 
    import json, random 
    from PIL import Image 
    a, b = PAIRS[(n - 1) % 6] 
    rnd = random.Random(n) 
    key = {} 
    for s in seeds: 
        left, right = (a, b) if rnd.random() < 0.5 else (b, a) 
        key[str(s)] = left 
        im_l = Image.open(os.path.join(folder, f"{left}_s{s}.jpg")).convert("RGB").resize((384, 384)) 
        im_r = Image.open(os.path.join(folder, f"{right}_s{s}.jpg")).convert("RGB").resize((384, 384)) 
        sheet = Image.new("RGB", (384 * 2 + 12, 384), "white") 
        sheet.paste(im_l, (0, 0)) 
        sheet.paste(im_r, (384 + 12, 0)) 
        sheet.save(os.path.join(folder, f"blind_{s}.png")) 
    json.dump(key, open(os.path.join(folder, "blind_key.json"), "w"), ensure_ascii=False) 
    return key
